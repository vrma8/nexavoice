# 1. IMPORTANT ARCHITECTURE CHANGE

The previous implementation was primarily phone/PSTN based.

**The new implementation is web-first.**

The product has two separate web experiences:

``` text
https://nexavoice.vercel.app/client/
https://nexavoice.vercel.app/support-agent/
```

## Client

The client can choose:

``` text
CHAT WITH AI
        OR
VOICE CALL WITH AI
```

### Chat mode

``` text
Client types message
        ↓
Client web app
        ↓
FastAPI
        ↓
Agora Conversational AI session / conversation bridge
        ↓
AI response
        ↓
Client chat UI
```

The client sees a normal chat interface:

``` text
You:
Mera application status kya hai?

AI:
Main aapka application status check karne mein
madad kar sakta hoon. Reference number batayein.
```

If required:

``` text
AI
 ↓
Escalation
 ↓
Human support agent
 ↓
Client continues in chat
```

### Voice mode

``` text
Client microphone
        ↓
Next.js client
        ↓
Agora RTC
        ↓
Agora Conversational AI Agent
        ↓
ASR → LLM → TTS
        ↓
Agora RTC
        ↓
Client speaker
```

The client experiences this as a browser-based call.

If escalation is required:

``` text
AI voice session
      ↓
Create case + handoff summary
      ↓
Support agent notified
      ↓
Support agent joins Agora channel
      ↓
AI stops / leaves / mutes
      ↓
Human continues with client
```

**Agora Conversational AI Engine is a mandatory part of the voice
implementation.** Agora provides the real-time AI voice-agent layer,
including configurable ASR, LLM and TTS pipelines, interruption handling
and noise suppression. citeturn2search1turn2search0

# 3. TWO CLIENT INTERACTION MODES

The client must have exactly two primary modes.

## A. Chat

Client uses:

-   Text input.
-   Send button.
-   Chat history.
-   AI responses.
-   Escalate-to-human action.
-   Human chat after escalation.

## B. Voice

Client uses:

-   Start call button.
-   Microphone permission.
-   Mute/unmute.
-   End call.
-   Speaker output.
-   Live conversation status.
-   Optional live transcript.
-   Human handoff.

The two modes share:

``` text
conversation_id
user/session identity
agent state
intent
collected information
confidence
case
transcript
escalation state
```

A user can start in chat and later switch to voice without losing the
case context, provided the same conversation/session is continued.

# 4. AGORA IS CENTRAL TO THE IMPLEMENTATION

Do not implement a separate homemade voice-agent pipeline when Agora
Conversational AI Engine can provide the required real-time voice-agent
functionality.

Agora Conversational AI supports configurable ASR, LLM and TTS providers
and is designed for real-time voice interaction. Agora also documents
intelligent interruption handling and background-noise suppression.
citeturn2search1

For the browser voice experience:

``` text
Next.js
   ↓
Agora Web RTC
   ↓
Agora channel
   ↓
Agora Conversational AI Agent
```

For the server-side agent lifecycle:

``` text
Next.js
   ↓
FastAPI
   ↓
Agora Conversational AI API / SDK
   ↓
Agent joins channel
```

Agora's current Agents SDK supports Python and TypeScript/Node.js and
wraps the Conversational AI API with agent/session management. The REST
API remains available as well. citeturn2search0turn2search2

**Important:** exact API payloads and SDK method names must be taken
from the current Agora documentation during implementation. Do not
invent Agora endpoints.

Official documentation:

https://docs.agora.io/en/

# 9. CHAT WITH AGORA CONVERSATIONAL AI

The requirement is to keep **Agora Conversational AI central**, but the
text interface should not pretend that a voice-only API is a normal REST
chatbot.

Use the appropriate Agora-supported mechanism for sending
text/instructions into an active Conversational AI session where
available. Agora's 2026 v2.6 release introduced the ability to inject
custom text instructions into an ongoing agent conversation, which is
useful for coordinating voice and text experiences. citeturn2search8

For the MVP, implement the text path behind a provider abstraction:

``` text
Chat UI
  ↓
FastAPI /api/chat/message
  ↓
ConversationService
  ↓
AgoraConversationAdapter
  ↓
Agora Conversational AI
```

The adapter must be replaceable.

``` python
class ConversationAdapter:
    async def send_text(self, conversation_id, text):
        ...

    async def get_response(self, conversation_id):
        ...
```

If the currently enabled Agora Conversational AI configuration does not
expose a suitable direct text interaction for the selected pipeline, use
the backend LLM path for chat while preserving the same agent state,
tools, escalation engine and conversation ID. Voice remains powered by
Agora Conversational AI.

Do not fabricate an unsupported Agora text API.

# 22. CONFIDENCE ENGINE

Use application-level confidence.

Inputs:

``` text
ASR confidence
Intent confidence
Entity confidence
Confirmation status
Conversation consistency
Repeated corrections
Noise/quality signals where available
```

Initial formula:

``` text
confidence =
    0.30 * intent_confidence
  + 0.25 * asr_confidence
  + 0.20 * entity_confidence
  + 0.15 * confirmation_score
  + 0.10 * consistency_score
```

Initial thresholds:

``` text
0.80 – 1.00 → HIGH
0.55 – 0.79 → MEDIUM
0.00 – 0.54 → LOW
```

These are experimental.

Tune using real test conversations.

------------------------------------------------------------------------

# 23. ESCALATION CONDITIONS

Escalate when:

``` text
Client explicitly asks for human
OR
Confidence remains low
OR
Client repeatedly corrects the AI
OR
Issue requires human judgment
OR
AI lacks required information
OR
AI tool/backend fails
OR
Request is outside permitted capabilities
OR
Safety policy requires human handling
```

The AI should not force the client to repeat the same information
indefinitely.

# 52. WHAT IS NO LONGER THE PRIMARY ARCHITECTURE

The old architecture assumed:

``` text
Caller Phone
   ↓
PSTN
   ↓
Telephony Provider
   ↓
Agora
   ↓
AI
```

That is **not the primary MVP path anymore**.

The new primary architecture is:

``` text
                    NEXAVOICE WEB
                         │
             ┌───────────┴───────────┐
             │                       │
          CLIENT                SUPPORT AGENT
             │                       │
      ┌──────┴──────┐                │
      │             │                │
     CHAT          VOICE             │
      │             │                │
      │         Agora RTC            │
      │             │                │
      │     Agora Conversational AI  │
      │             │                │
      └──────┬──────┘                │
             │                       │
             ▼                       ▼
                  FASTAPI
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
      Agent State  Cases     PostgreSQL
          │
          ▼
     Shared Tools
```

PSTN/telephony can be added later as an optional channel:

``` text
Future:

Phone
  ↓
PSTN/SIP
  ↓
Agora
  ↓
Same Conversational AI + Agent Logic
```

This keeps the core agent architecture reusable.

# 53. IMPORTANT IMPLEMENTATION RULES

Any AI coding assistant working on this repository MUST:

1.  Read this implementation document before changing architecture.
2.  Use Agora Conversational AI Engine for the voice-agent path.
3.  Use Agora Web SDK for browser voice media.
4.  Keep Agora-specific code under `backend/app/agora/` and/or clearly
    isolated frontend Agora helpers.
5.  Never expose Agora App Certificate or Customer Secret.
6.  Never hardcode API keys.
7.  Never invent Agora API endpoints or SDK methods.
8.  Check current Agora documentation before implementing an Agora
    feature.
9.  Keep business logic independent of Agora-specific APIs.
10. Share conversation state between chat and voice.
11. Keep human takeover in the same conversation/session whenever
    technically possible.
12. Never let the LLM execute raw SQL.
13. Never fabricate application data.
14. Add tests for confidence, state, confirmation and escalation.
15. Update this document when the architecture materially changes.
16. Prefer small incremental changes.
17. Do not reintroduce PSTN as the primary client interface unless
    explicitly requested.

# 55. FINAL SYSTEM PRINCIPLE

The system has **one conversation engine** with multiple interfaces:

``` text
                 ONE CONVERSATION
                       │
          ┌────────────┼────────────┐
          │            │            │
         CHAT         VOICE       HUMAN
          │            │            │
          └────────────┼────────────┘
                       │
                 Shared State
                       │
                 Shared Tools
                       │
                 Shared Case
```

The client chooses how to communicate:

``` text
TEXT
or
VOICE
```

The AI handles the first interaction.

When the AI is uncertain or the client needs a person:

``` text
AI
 ↓
CONTEXT PRESERVED
 ↓
HUMAN
```

The central product principle remains:

> **The AI should know when it should stop being the AI.**
